# Lot 16 — Export / import de projet

Détail du lot (sous-tâches et notes). Mode d'emploi et synthèse : [avancement.md](../avancement.md).

> Ajouté le 16/11/2026 (décision d'Allan) : sorti du lot 12 bis (anciennes sous-tâches 12b.2 et 12b.3), **intégré à la V1** et fait **avant le lot 12 bis**, qui s'en sert pour transférer un projet du PC vers la tablette et dont le lecteur `.zip` lit ce format. Exigences : PRD PRJ-05, VID-13, PRS-07 ; TRD §12 (export, sauvegarde / restauration).
>
> ✅ Décisions (Allan, 16/11/2026) :
>
> - **Format** : un `.zip` contenant un fichier JSON (toutes les données du projet) et chaque fichier son, vidéo et image de battlemap. Pas de partie sauvegardée dans l'export.
> - **Bibliothèque zip** : **`@zip.js/zip.js`** (export et import en flux ; étude dans la note de 16.3).
> - **Vidéos lourdes exclues par défaut** : une vidéo de **plus de 500 Mo** (`LARGE_VIDEO_BYTES`) n'est pas cochée par défaut dans l'export (le MJ peut la cocher).
> - **Identifiants conservés** à l'import (pas de nouveaux `id`). Un **média** dont l'`id` existe déjà n'est **pas réimporté** (un média ne change jamais après son import). Les autres objets dont l'`id` existe déjà sont **écrasés**.
> - **Bibliothèque** : à l'import, tous les sons et vidéos du zip (bibliothèque du projet **et** bibliothèque globale à l'export) vont dans la **bibliothèque du projet**. Un média déjà présent n'est pas réimporté.
> - **Projet déjà présent** : l'import demande confirmation (« Le projet « X » existe déjà et sera remplacé », avec les dates de modification).
> - **Tout le zip est importé** ; les objets locaux du projet absents du zip ne sont **pas** supprimés.
> - **Vidéo référencée mais absente du zip** : la vidéo est créée dans la bibliothèque du projet (même identifiant, sans fichier) ; la Bibliothèque affiche une **alerte** sur cette vidéo et permet d'**importer son fichier plus tard**. La vidéo garde son identifiant : les actions qui la lancent liront la vidéo importée.
> - **Parties sauvegardées** : ni exportées, ni modifiées par l'import.
> - **Dupliquer un projet** : noté dans les idées d'évolution (après la V1), pas fait maintenant.
>
> ✅ Décisions (Allan, 16/11/2026, au lancement du lot) :
>
> - **Firefox** (pas de `showSaveFilePicker()`) : zip construit en mémoire puis téléchargé ; au-delà d'environ 2 Go, avertissement (conseiller Chrome / Edge ou d'exclure des vidéos). Chrome et Edge : écriture en flux sur le disque.
> - **Sons et vidéos venus de la bibliothèque globale** : à l'import, leurs **dossiers d'origine** sont recréés dans la bibliothèque du projet avec leurs identifiants (seulement les dossiers qui mènent à un élément exporté) ; un dossier dont l'`id` existe déjà n'est pas recréé (pas de doublon au réimport sur le PC d'origine).
> - **Choix des vidéos à l'export** : pas de liste par vidéo. Une case **« Inclure les vidéos »** (cochée par défaut) et une seconde case pour **inclure aussi les vidéos de plus de 500 Mo** (décochée par défaut) ; poids de l'export mis à jour.
> - **Import** : bouton **« Importer un projet »** dans l'accueil, à côté de « Nouveau projet » (pas de glisser-déposer).
> - Choix techniques proposés (sans objection) : zip = `projet.json` (format versionné) + `medias/<id>.<ext>`, fichier nommé `<Nom du projet>.zip` ; import = médias d'abord (un par un), puis toutes les données en une transaction ; en cas d'erreur, d'annulation ou de quota dépassé, les médias déjà écrits sont supprimés ; place libre estimée vérifiée avant l'import ; fenêtre de progression avec « Annuler » à l'export et à l'import.

    - ℹ️ Bibliothèques zip étudiées (16/11/2026, versions npm du jour) :
      - **fflate** 0.8.3 (MIT) : rapide, léger, découpable (tree-shaking), lecture et écriture, flux (`Zip` / `Unzip`), Web Workers.
